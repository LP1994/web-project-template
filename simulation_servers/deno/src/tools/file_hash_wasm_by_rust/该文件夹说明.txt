该文件夹下是用Rust代码编写的文件哈希值计算工具，然后将Rust代码编译为wasm，以便供JS、TS调用。
建议查阅下面写到的“实际测试”结论说明！！！



new FileHasher()    创建哈希计算实例
update(chunk)   输入一块文件数据，更新四种哈希状态
digest()    获取当前数据的全部哈希结果
digestInto(result)  将结果写入你传入的对象
reset() 清空状态，重新开始计算
bytesProcessed()    返回已经处理的字节数

实际测试后，发现wasm跟使用node编写的增量计算超大文件的哈希值的耗时简直是天壤之别，使用wasm的耗时几乎是node的17倍！！！

# 启用 WASM SIMD128
$env:RUSTFLAGS = "-C target-feature=+simd128"
能减少sha224(别名：sha-224、sha2-224)、sha256(别名：sha-256、sha2-256)、sha384(别名：sha-384、sha2-384)、sha512(别名：sha-512、sha2-512)的耗时，缩短跟node版的耗时差距。是node的2.8倍，未启用 WASM SIMD128前，是node的4.4倍。

查看编译后的.wasm是否开启了“SIMD128”：
1、
wasm2wat .\FileHashWasmByRust_bg.wasm -o .\FileHashWasmByRust_bg.wat
2、
Select-String -Path .\FileHashWasmByRust_bg.wat -Pattern "v128|i32x4|i64x2|i8x16|i16x8"

编译例子：
wasm-pack build --release --no-gitignore --no-pack --target deno --out-dir $DistDir

需要项目根目录下“.cargo/config.toml”配合配置如下关键配置项：
[build]
target = "wasm32-unknown-unknown"

[target.wasm32-unknown-unknown]
rustflags = [
  "-C",
  # 启用 WASM SIMD128
  "target-feature=+simd128"
]

需要项目根目录下"Cargo.toml"配合配置如下关键配置项：
[profile.release]
opt-level = 3

[package.metadata.wasm-pack.profile.release]
wasm-opt = [
  "-O3"
]
