真正适合 Wasm 的场景通常包括：
- 大规模数值计算；
- 图像和音频处理；
- 加密和哈希算法；
- 压缩和解压；
- 复杂的数据解析；
- 计算密集型算法；
- 需要复用已有 Rust/C/C++ 算法库的场景。
尤其是大批量数据处理，应该尽量减少 JavaScript 和 Rust 之间频繁的小数据交换，采用批量传递 TypedArray 等方式。



普通 WebAssembly 核心模块：推荐用于 JavaScript / TypeScript 功能扩展。
Rust 编译目标：
wasm32-unknown-unknown
它表示生成面向通用 WebAssembly Runtime 的 32 位 Wasm 模块，不依赖某一个特定操作系统。
它适合编译数学运算、算法、解析器等不需要直接访问操作系统接口的功能。
典型用途：
- 数学运算、数据处理。
- 图像、音频和视频处理。
- 哈希、加密、压缩算法。
- 自定义解析器。
- 独立算法模块。
这类模块主要通过 WebAssembly 导入、导出接口与宿主 JavaScript 交互。
特别注意：这个目标本身不提供操作系统接口，诸如 std::fs 的文件操作不能直接使用，std::thread::spawn 也不能正常工作。
如果你的目的是将独立功能编译为 .wasm，然后由 JavaScript/TypeScript 直接导入调用，那么通常优先考虑这个方案！！！
例子：
1、安装依赖：
rustup target add wasm32-unknown-unknown wasm32-unknown-emscripten

2、编译命令：
cargo build --target-dir ./out --release --target wasm32-unknown-unknown

3、编译完成后，你会得到(就在当前执行命令的文件夹下，默认是这么输出的)：
target/wasm32-unknown-unknown/release/wasm_demo.wasm

例子：“MathTool.rs”、“Cargo.toml”都在同一个文件夹层级下，编译命令也是在这个文件夹层级下执行的。

// MathTool.rs的内容：
// #[unsafe(no_mangle)] → 禁止 Rust 对导出符号名称进行名称改编。不执行 Rust 符号名称修饰，保留导出名称。Rust 2024语法这么要求写的！
// #[unsafe(no_mangle)] 是 Rust 1.82 才引入的语法！可以同时适用于 Rust 2021 和 Rust 2024 Edition（前提是 Rust 编译器版本不低于 1.82）。
// pub：将函数声明为公开函数。允许函数被外部访问。
// extern "C" → 指定 C ABI，采用 C ABI 调用约定。定义跨语言调用使用的函数调用约定。
#[unsafe(no_mangle)]
pub extern "C" fn Add(a: i32, b: i32) -> i32 {
    a + b
}

// Cargo.toml的内容：
[package]
# 要生成的 .wasm 文件的名称。
name = "MathTool"
version = "1.0.0"
# edition可有值：2015、2018、2021、2024
edition = "2024"

[lib]
# 要生成的 .wasm 文件的名称。
name = "MathTool"
# Rust源码文件路径。
path = "MathTool.rs"
#生成适合外部运行环境加载的动态链接库形式，对 wasm32-unknown-unknown 目标来说，cdylib 对应的“动态库文件”就是 .wasm 文件（因为目标平台不是 Windows/Linux/Mac，所以扩展名不是 .dll/.so/.dylib，而是 .wasm）。
crate-type = ["cdylib"]

注意：
这种方式有一个很大的好处：你不需要额外引入 wasm-bindgen，就可以完成简单的基础类型函数调用。
不过，它也有明显的限制：WebAssembly Core 的基础函数接口并不直接理解 Rust 的 String、Vec<T>、结构体或者复杂对象。

WASI 模块 / WebAssembly Component：适合跨运行环境的独立程序或组件。
主要适合独立算法和功能模块。
但假如你希望 Rust 编写的程序能够在 Wasm 中访问文件系统、环境变量、命令行参数、时钟等资源，就需要了解 WASI。
WASI 全称：WebAssembly System Interface。
它为 Wasm 程序定义了一套与宿主操作系统交互的标准接口。
Rust 编译目标：
wasm32-wasip1
wasm32-wasip2
典型用途：
- 独立运行的 Wasm 程序。
- 文件系统访问。
- 环境变量、时钟等系统接口。
- 跨宿主环境部署的功能组件。
WASI Preview 2 使用 Component Model，与普通 WebAssembly 核心模块不是同一种二进制接口形式。
Preview 2 与 Preview 1 有较大区别。
它基于：WebAssembly Component Model。
组件模型不仅提供宿主系统接口，还支持通过标准化接口定义组件之间的交互。

需要安装：
rustup target add wasm32-wasip1 wasm32-wasip2

WASI Preview 2 的 Component 并不是普通的 Core Wasm 模块。
因此不能直接使用：
WebAssembly.instantiate(...)
也不能简单地写：
import component from "./component.wasm";

wasm-bindgen（https://github.com/wasm-bindgen/wasm-bindgen）：
涉及字符串、数组、对象等复杂数据类型，那么一定需要 wasm-bindgen，它主要解决 Rust 与 JavaScript 之间的类型转换和函数调用问题。
wasm-bindgen 会生成必要的 JavaScript 胶水代码，负责参数传递、内存分配、字符串转换等工作。
它还支持处理其他复杂类型，例如：
- String
- Vec<T>
- Option<T>
- JavaScript 对象
- JavaScript 函数
- 自定义结构体（通过相应绑定方式）
wasm-bindgen 不只是生成一个 JavaScript 文件，它还会处理 Wasm 模块，使其能够使用生成的 JavaScript Glue Code 完成高层类型交互。
因此，正常情况下不能只拿 Rust 编译出来的原始 .wasm 文件，就直接调用其中的字符串、对象等高层接口。需要同时使用生成的 JavaScript 包装模块。

支持的 Rust 类型及其在 JavaScript 中的表示形式
本节概述了 wasm-bindgen 可以在 WebAssembly ABI 边界两侧发送和接收的所有类型，以及它们如何转换为 JavaScript。见：
https://rustwasm.github.io/docs/wasm-bindgen/reference/types.html

例子：
use wasm_bindgen::prelude::*;

// #[wasm_bindgen] 是一个 Rust 过程宏（Procedural Macro）。
// 它会在编译阶段参与生成互操作所需的接口描述和相关代码。随后，wasm-bindgen CLI 会处理编译结果，生成对应的 JavaScript 包装模块及适配后的 Wasm 模块。
#[wasm_bindgen]
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[wasm_bindgen]
pub fn greet(name: String) -> String {
    format!("你好，{}！", name)
}

// 将 JavaScript 函数导入给 Rust
// 这里的 extern "C" 块是用来声明外部 JavaScript 函数，由 wasm-bindgen 将这个声明转换成 JavaScript 导入接口。
#[wasm_bindgen]
extern "C" {
    fn alert(message: &str);
}

// 将 Rust 函数导出给 JavaScript
#[wasm_bindgen]
pub fn show_message() {
    alert("Hello from Rust!");
}

wasm-pack（https://github.com/wasm-bindgen/wasm-pack）
该工具旨在成为构建和使用 Rust 生成的 WebAssembly 的“一站式解决方案”，这些 WebAssembly 代码可与 JavaScript 进行互操作，无论是在浏览器中还是在 Node.js 环境中。wasm-pack 可帮助您构建由 Rust 生成的 WebAssembly 包，这些包既可以发布到 npm 注册表，也可以在您现有的工作流（如 webpack）中与任何 JavaScript 包配合使用。

安装：
cargo install wasm-pack

wasm-pack 会负责协调 Cargo 编译、wasm-bindgen 处理以及最终包的生成。
因此，正常使用 wasm-pack 时，不需要另外手动安装一个独立的 wasm-bindgen CLI。

补充：如果你以后希望直接使用 wasm-bindgen 命令行工具，不通过 wasm-pack，则可以单独安装：
cargo install wasm-bindgen-cli

wasmbuild（https://github.com/denoland/wasmbuild#wasmbuild）
wasmbuild 是 Deno 官方提供的 Rust + WebAssembly 构建工具。
它主要负责自动完成：
1. Rust 项目构建。
2. 将 Rust 编译为 WebAssembly。
3. 生成 wasm-bindgen JavaScript 胶水代码。
4. 生成 TypeScript 类型声明。
5. 将生成文件组织到 Deno 项目中。
基本使用过程：
第一步：创建项目
deno run -A jsr:@deno/wasmbuild new
第二步：编写 Rust 代码
在生成的 rs_lib 目录下编写 Rust 模块。如：
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[wasm_bindgen]
pub fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}

#[wasm_bindgen]
pub fn sum(numbers: Vec<i32>) -> i32 {
    numbers.iter().sum()
}
第三步：构建
deno task wasmbuild
第四步：在 TypeScript 中调用
import { add } from "./lib/rs_lib.js";
console.log(add(1, 1));

注意：
#[wasm_bindgen] 是关键。
它告诉绑定工具，这些函数需要暴露给 JavaScript 使用。
注意：这是通过 wasm-bindgen 提供的跨语言类型转换接口，并不是 WebAssembly Core 原生支持 Rust 字符串或 JavaScript 数组。

不进行优化，适合调试：
deno task wasmbuild --debug

将 Wasm 内容内嵌到生成的 JavaScript 中，适合需要兼容不支持 Wasm ES Module Integration 的环境：
deno task wasmbuild --inline

检查生成的 Wasm 和绑定文件是否与 Rust 源代码保持同步：
deno task wasmbuild --check

Rust + wasm-bindgen + wasm-pack：这条路线非常适合将 Rust 编写的业务逻辑编译成 WebAssembly（Wasm），然后作为一个 JavaScript 模块提供给浏览器、Webpack、Vite、Node.js 等 JavaScript 运行环境使用。

路线：
Rust 业务代码(Cargo 项目)：数据结构、算法、计算逻辑、业务规则
--->
rustc 编译
--->
WebAssembly（.wasm）：运行在浏览器 Wasm 虚拟机中的二进制模块
--->
wasm-bindgen：生成及处理互操作代码
--->
JavaScript Bindings：JavaScript 包装模块、类型转换、函数调用接口
--->
wasm-pack：打包输出
--->
JavaScript 生态：原生浏览器、Webpack、Vite、Node.js、Deno

创建项目：
// 这里使用 --lib，而不是 --bin，因为我们需要构建一个供 JavaScript 调用的 Rust 库，而不是一个独立运行的 Rust 命令行程序。
cargo new rust-math --lib

cd rust-math

编译 Rust 项目并生成 JavaScript Bindings：
开发期间（开发版更适合快速编译和调试）：
wasm-pack build --target web --dev
生产构建（生产版则采用优化后的代码）：
wasm-pack build --target web --release
直接执行（wasm-pack build 默认采用 release 构建配置。）：
wasm-pack build --target web

--target：它决定生成的 JavaScript 包装代码采用什么方式加载 Wasm 模块。
详细见：
https://wasm-bindgen.github.io/wasm-bindgen/reference/deployment.html#deploying-rust-and-webassembly
构建目标         使用环境              主要用途
web             原生浏览器            不依赖前端打包工具
bundler         Webpack等打包工具	    集成到前端工程
nodejs          Node.js             CommonJS 模块
deno            Deno                原生 ES Module
额外还有：
experimental-nodejs-module：可通过 import 作为 Node.js ESM 模块加载。
module：使用新的源代码阶段导入语法来获取编译后的 WebAssembly 模块。
PS：
此外还有 no-modules，属于不使用 ES Module 的旧式浏览器加载方式，一般不建议新项目采用。

这个命令会自动完成一系列操作：
1. Cargo 编译
   调用 Rust 工具链，将项目编译为 wasm32-unknown-unknown 对应的 Wasm 产物。
2. wasm-bindgen 处理
   生成 Rust 和 JavaScript 之间的绑定代码，并处理 Wasm 模块。
3. 生成 JavaScript 模块
   生成供 JavaScript 使用的 .js 包装文件。
4. 生成 TypeScript 声明
   根据导出接口生成 .d.ts 类型声明文件。
5. 组织输出文件
   将 Wasm、JavaScript、类型声明文件以及包信息放进 pkg 目录。

生成的文件说明：
rust_math_bg.wasm        实际的 WebAssembly 二进制模块
rust_math.js             JavaScript 包装模块
rust_math.d.ts           JavaScript 模块的 TypeScript 声明
rust_math_bg.wasm.d.ts   Wasm 底层模块声明
package.json             生成的包元数据
README.md                包说明文件（存在源 README 时）

这里需要特别注意不同--target之间的使用区别：
--target web
JavaScript 实际应该导入的是 rust_math.js，而不是直接导入 rust_math_bg.wasm。
import init, {
    add,
    greet
} from "./pkg/rust_math.js";
rust_math.js 才是 wasm-bindgen 生成的高层调用接口。
需要调用：
await init();
之后才能开始使用各个Rust提供的方法。

--target bundler
import {
    add,
    greet,
    Counter
} from "./pkg/rust_math.js";
console.log(add(100, 200));
这里与 web 最大的区别是：
bundler 模式由前端打包工具负责处理 Wasm 模块的加载，不需要像原生浏览器模式那样显式执行默认的 init()。
也就是说这种构建是无需调用：
await init();
之后才能开始使用各个Rust提供的方法。
将 wasm-pack 集成到 Webpack 构建流程：
可以使用如下包来集成：@wasm-tool/wasm-pack-plugin（https://github.com/wasm-tool/wasm-pack-plugin）
这样可以让 Webpack 构建时自动触发 Rust 项目编译。
官方示例中也提供了这种项目结构和插件集成方式：
https://rustwasm.github.io/docs/wasm-pack/tutorials/hybrid-applications-with-webpack/using-your-library.html
https://github.com/rustwasm/rust-webpack-template/tree/master

--target nodejs
Node.js 侧使用 CommonJS：
const rustMath = require("./pkg/rust_math.js");
console.log(
    rustMath.add(100, 200)

这种方式适合将 Rust 算法库用于 Node.js 服务端程序。

--target deno
Deno 可以直接导入生成的 ES Module。
import {
    add,
    multiply,
    greet
} from "./pkg/rust_math.js";
console.log(add(10, 20));

JavaScript Object 与 Rust Struct
建议使用：serde + serde-wasm-bindgen
例如 Rust：
#[derive(Serialize, Deserialize)]
pub struct Product {
    pub id: u32,
    pub name: String,
    pub price: f64,
}
JavaScript：
const product = {
    id: 1001,
    name: "Keyboard",
    price: 299.5
};
传入 Rust：
let product: Product =
    serde_wasm_bindgen::from_value(value)?;
转换回来：
let value =
    serde_wasm_bindgen::to_value(&product)?;
JavaScript 得到的仍然是一个普通对象。
需要注意：Serde 转换与 JSON 字符串序列化不是一回事。它可以直接处理 JavaScript 值，不需要先执行 JSON.stringify() 再进行字符串解析。具体类型支持仍受 Serde 和 serde-wasm-bindgen 的映射规则约束。

异步函数与 Promise
Rust：
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub async fn calculate_async(
    a: f64,
    b: f64,
) -> Result<f64, JsValue> {

    Ok(a + b)
}
JavaScript：
const result = await calculate_async(10, 20);

console.log(result);
wasm-bindgen 会将导出的 Rust async fn 转换成 JavaScript Promise 接口。
如果需要在 Rust 内部等待 JavaScript 的 Promise，还可以使用，在 Cargo.toml 中添加：

然后利用 JsFuture 将 JavaScript Promise 转成 Rust Future。

https://rustwasm.github.io/docs/wasm-bindgen/print

Rust 调用浏览器 API
这就涉及两个重要的 Rust Crate：
js-sys：JavaScript 内置对象和 API 的 Rust 类型封装
web-sys：浏览器 Web API 的 Rust 类型封装
例如：
- DOM 操作
- Canvas
- Fetch
- WebSocket
- Web Storage
- Web Workers
- Web Audio
如果希望 Rust 直接操作 DOM，可以这样配置。
在 Cargo.toml 中添加：
[dependencies]
js-sys = "0.3.107"

web-sys = {
  version = "0.3.107",
  features = [
    "Window",
    "Document",
    "Element"
  ]
}
Rust 代码：
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn set_page_text(
    text: &str
) -> Result<(), JsValue> {

    let window = web_sys::window()
        .ok_or_else(|| {
            JsValue::from_str("无法获取 Window")
        })?;

    let document = window.document()
        .ok_or_else(|| {
            JsValue::from_str("无法获取 Document")
        })?;

    let element = document
        .get_element_by_id("app")
        .ok_or_else(|| {
            JsValue::from_str("找不到 app 元素")
        })?;

    element.set_text_content(Some(text));

    Ok(())
}
JavaScript：
import {
    set_page_text
} from "./pkg/rust_math.js";

set_page_text("Hello from Rust!");
HTML：
<div id="app"></div>
这样 Rust 就能通过 web-sys 操作浏览器 DOM 了。
官方提供了 DOM、Canvas、Fetch、WebSocket 等大量示例：
https://rustwasm.github.io/docs/wasm-bindgen/reference/types.html
不过，我更建议实际项目采用职责分离：
- JavaScript / TypeScript：处理 DOM、UI、路由、事件、浏览器交互。
- Rust：处理复杂算法、数据解析、加密计算、计算密集型业务。
- wasm-bindgen：负责双方之间的数据和函数接口。
除非业务确实要求 Rust 直接控制浏览器 API，否则没有必要把所有前端逻辑都迁移到 Rust。

构建命令整理
实际开发过程中，建议记住以下命令：
cargo new rust-math --lib：创建 Rust 库项目
cargo check：检查原生 Rust 代码
cargo check --target wasm32-unknown-unknown：检查 Wasm 目标代码
cargo build：编译原生 Rust 项目
cargo build --target wasm32-unknown-unknown：编译 Wasm 目标
wasm-pack build --target web --dev：生成浏览器开发版
wasm-pack build --target web --release：生成浏览器生产版
wasm-pack build --target bundler：生成打包工具使用的模块
wasm-pack build --target nodejs：生成 Node.js 模块
wasm-pack build --target deno：生成 Deno 模块
wasm-pack test --headless --chrome：在无头 Chrome 环境运行 Wasm 测试
注意：不同 target 默认都会使用 pkg 作为输出目录。需要同时保留不同环境的产物时，可以指定不同的输出目录：
wasm-pack build --target web --out-dir pkg-web
wasm-pack build --target bundler --out-dir pkg-bundler
wasm-pack build --target deno --out-dir pkg-deno
这样就不会出现后一次构建覆盖前一次构建产物的问题。

# - 机器学习中的向量计算。
# - 网络数据处理中的批量字节操作。

编译例子：
wasm-pack build --release --no-gitignore --no-pack --target deno --out-dir $DistDir

需要项目根目录下“.cargo/config.toml”配合配置如下关键配置项：
[build]
target = "wasm32-unknown-unknown"

[target.wasm32-unknown-unknown]
rustflags = [
  "-C",
  # 启用 WASM SIMD128
  "target-feature=+simd128"
]

需要项目根目录下"Cargo.toml"配合配置如下关键配置项：
[profile.release]
opt-level = 3

[package.metadata.wasm-pack.profile.release]
wasm-opt = [
  "-O3"
]
